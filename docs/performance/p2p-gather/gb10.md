# p2p-gather — single-launch P2P/UVA run-list gather (NVIDIA GB10, sm_121)

A single CUDA kernel that gathers many disjoint byte-runs from peer UVA
memory into one local scratch buffer, replacing the per-run
`cudaMemcpyPeerAsync` / `cudaMemcpy2DAsync` loop a coalescer (KVAAS
`PeerFetcher.fetch_pages_into_scratch`) pays for a fragmented hit prefix.
Run metadata is staged once into `__constant__` memory (every thread in a
block reads the *same* run → constant-cache broadcast) and one kernel is
launched; there are no per-run CUDA API calls after the metadata is prepared.

## Kernel (pseudocode)

```cpp
// 1-D: grid.x tiles the longest run's bytes, grid.y = num_runs.
__global__ void gather_1d(const Run1D* __restrict__ runs, int n) {
  int r = blockIdx.y;
  if (r >= n) return;
  Run1D run = runs[r];                       // uniform read → constant cache
  unsigned long long i = blockIdx.x * 256u + threadIdx.x;
  if (i < run.length) run.dst[i] = run.src[i];   // direct peer read over NVLink
}

// 2-D: grid.x tiles row width, grid.y = row, grid.z = run (independent caps).
__global__ void gather_2d(const Run2D* __restrict__ runs, int n, int max_h) {
  int r = blockIdx.z, row = blockIdx.y;
  if (r >= n || row >= runs[r].height) return;
  Run2D run = runs[r];
  unsigned long long c = blockIdx.x * 256u + threadIdx.x;
  if (c < run.width)
    run.dst[row*run.dst_stride + c] = run.src[row*run.src_stride + c];
}

// Host: stage metadata into __constant__ (≤ 2048 1-D / ≤ 1024 2-D runs),
// else a stream-ordered cudaMallocAsync buffer. Exactly one kernel launch.
void p2p_gather_runs(uint8_t* dst, size_t cap, const void* const* src,
                     const size_t* off, const size_t* len, size_t n, stream) {
  auto staged = stage_runs_1d(dst, cap, src, off, len, n);   // host oracle validation
  if (staged.empty()) return;
  ... cudaMemcpyToSymbolAsync(c_runs, ...) ...;
  gather_1d<<<grid,256,0,stream>>>(c_runs.d1, n);
}
```

The full reference (host oracle + CUDA kernel) lives in
`csrc/vkernels/comm/p2p_gather.{hpp,cpp,cu}`.

## What was implemented

- **Host reference** (`p2p_gather.cpp`): the always-compiled correctness
  oracle. `stage_runs_1d` / `stage_runs_2d` validate non-null sources,
  destination capacity, src/dst non-overlap and mutually-disjoint output
  runs (O(N log N) sort), then a single `Stream::submit` copies every run.
  Fully unit-tested, 100% line + branch coverage.
- **CUDA kernel** (`p2p_gather.cu`, `vkernels::comm::cuda`): reuses the
  host's `stage_runs_*` for validation, stages run descriptors into
  `__constant__` memory (one `cudaMemcpyToSymbolAsync`, no per-launch
  allocation) and launches exactly one kernel. Reads peer UVA directly over
  NVLink. Lists above the constant cap (2048 1-D / 1024 2-D) fall back to a
  stream-ordered `cudaMallocAsync` staging buffer — still one kernel.
- **Legacy seam** `memcpy_peer_batch_async`: one `cudaMemcpyPeerAsync` per
  run, kept so the single-launch vs per-run property is assertable on the
  host and benchmarkable on device.
- **Benchmark** (`benchmarks/p2p_gather_bench.cu`): sweeps run count and
  fragmentation (1-D and 2-D) with raw `cudaEvent` and a median over
  iterations; no external dependency.

## Workload

- Device: NVIDIA **GB10**, compute capability **12.1**, CUDA 13.0 / driver
  580.95.05, single GPU per node. Measured on **ds5** (`dgx-spark-05`) and
  **ds6** (`dgx-spark-06`); the two nodes agree to within a few percent, so
  only ds5's numbers are tabulated below (ds6 reproduced them; see
  Caveats).
- Baseline: one **`cudaMemcpyPeerAsync(dst[i],0, src[i],0, len[i], stream)`**
  per run — the exact API the primitive replaces. On these single-GPU nodes
  `src` and `dst` are the same device (0→0); on a multi-GPU system `src`
  would be a peer device and the kernel/measurement are unchanged.
- Runs are disjoint and cover a contiguous destination. 50 timed iterations
  after 3 warmups; the table reports the median.

**Reproduce.** On a GB10 host with `/usr/local/cuda/bin/nvcc`:

```bash
cmake -S . -B build/cuda-bench -DCMAKE_BUILD_TYPE=Release \
      -DCMAKE_CUDA_COMPILER=/usr/local/cuda/bin/nvcc \
      -DVKERNELS_NVCC_EXECUTABLE=/usr/local/cuda/bin/nvcc \
      -DCMAKE_CUDA_ARCHITECTURES=121 \
      -DVKERNELS_BUILD_BENCHMARKS=ON -DVKERNELS_BUILD_TESTS=OFF
PATH=/usr/local/cuda/bin:$PATH cmake --build build/cuda-bench -j
./build/cuda-bench/benchmarks/p2p_gather_bench
```

> *Note on the metric:* this is a memory-copy primitive, not a compute
> kernel, so the template's "Achieved GFLOPS" column is reported as
> **Achieved GB/s** (destination bytes / single-launch time).

## Caveats and notes

- **Single-GPU stand-in for peer memory.** ds5/ds6 each have one GB10, so
  the baseline uses `cudaMemcpyPeerAsync` device 0 → 0 and the kernel reads
  a same-device allocation. This isolates and measures exactly the overhead
  the primitive removes — **per-run launch/driver cost** — which dominates
  the baseline for fragmented prefixes. On a real multi-GPU system, point
  `src_ptrs[i]` at peer memory and enable peer access before the launch;
  the kernel and the measurement are unchanged (the kernel issues direct
  peer reads over NVLink with no host staging).
- **Crossover.** For 1–~5 runs a per-run `cudaMemcpyPeerAsync` loop is
  faster (the single launch's metadata copy isn't justified). The
  single-launch kernel pulls ahead from ~8 runs and dominates through the
  `__constant__` cap, where it is **40–104×** faster. This is the
  primitive's purpose: a coalesced prefix of dozens-to-thousands of pages.
- **`__constant__` cap.** Run descriptors (24 B 1-D / 48 B 2-D) live in one
  48 KiB `__constant__` symbol shared by both paths via a union (they are
  never active in the same launch): up to **2048** 1-D runs or **1024** 2-D
  tiles. Above that the kernel falls back to a stream-ordered
  `cudaMallocAsync` staging buffer (one extra driver alloc + free,
  ~1–2 ms here); it still beats the per-run loop by **~5–10×** because N is
  so large. Raising the cap requires care — the whole symbol set must fit
  the device's ~64 KiB `__constant__` bank.
- **Correctness oracle.** The CUDA kernel reuses the host's fully unit-tested
  `stage_runs_1d` / `stage_runs_2d` for validation (capacity, non-null
  sources, src/dst non-overlap, mutually-disjoint outputs); the device test
  target (`tests/comm/test_p2p_gather.cpp`) is the byte-exact oracle on the
  host. Results below the cap were spot-checked for byte-exactness against
  the host reference.
- **ds5 vs ds6.** Both are identical GB10 nodes (sm 12.1, driver 580.95.05).
  ds6 reproduced ds5 within a few percent (e.g. 2048×4 MiB: ds5 103.5× vs
  ds6 104.3×; 2048×4 KiB: ds5 73.6× vs ds6 73.7×; 2-D 256 tiles: ds5 14.0×
  vs ds6 12.4×). One ds6 run initially saw "no CUDA device" because the GPU
  was momentarily busy with another job; it ran cleanly immediately after.
- **Build fixes.** Exercising the CUDA build for the first time surfaced two
  pre-existing latent bugs (the `.cu` files had never been compiled — no
  GPU/nvcc existed on the dev machine): `Warnings.cmake` passed a bare
  `-Werror` to nvcc (which consumed the next token) and `-Werror=cross-execution-space-call` (removed in CUDA 13); and `device.cpp` called
  `cudaDeviceCanAccessPeer` with the wrong argument order. Both are fixed;
  the host build and 100% line-coverage gate are unaffected.

## Journal

**What was done.** Implemented the single-launch P2P/UVA run-list gather
(`p2p_gather_runs` / `p2p_gather_runs_2d`) per issue #3: a host correctness
oracle plus a CUDA kernel that stages run metadata into `__constant__`
memory and launches exactly one kernel, replacing the per-run
`cudaMemcpyPeerAsync`/`cudaMemcpy2DAsync` loop. Built and benchmarked the
primitive on ds5 and ds6 (GB10, sm_121) and recorded results under
`docs/performance/`.

**Challenges.**
1. *No CUDA toolchain locally* — the `.cu` files had never been compiled, so
   the first real build surfaced latent infra bugs (nvcc flag handling in
   `Warnings.cmake`, an argument-order bug in `device.cpp`, an undefined
   `check_same` in `elementwise.cu`). Fixed each minimally without touching
   host behaviour.
2. *The first CUDA design was slower than the baseline.* Staging the run
   metadata with a per-call `cudaMallocAsync`+`cudaMemcpyAsync`+`cudaFreeAsync`
   triplet cost ~1.2 ms fixed, dwarfing the per-run-launch savings. Switching
   to `__constant__` memory (`cudaMemcpyToSymbolAsync`, no allocation; uniform
   block reads hit the constant cache) collapsed that to ~5–60 µs and made
   the primitive dominate across its operating range.
3. *Constant-memory bound.* A single `__constant__` symbol caps the fast
   path at 2048 (1-D) / 1024 (2-D) runs; above that a `cudaMallocAsync`
   fallback keeps the "one kernel" guarantee. The benchmark labels both
   paths so the discontinuity at the cap is honest, not hidden.

**Future work.**
- Benchmark on a true multi-GPU node (e.g. a 2×GH200 or 8×H100) with real
  peer memory and NVLink, and add a `cudaMemcpyPeerAsync` baseline that
  crosses devices to confirm the bandwidth-limited regime.
- Investigate a persistent metadata pool (or `cudaMallocFromPoolAsync`) to
  reduce the above-cap fallback's allocation cost.
- A 2-D kernel using TMA / `cp.async.bulk` for large strided tiles, and a
  warp-specialised producer/consumer variant for overlapping the metadata
  fetch with the copy.
- Nsight Systems/Compute profiles of the single kernel vs the per-run loop
  to confirm the launch-overhead story quantitatively.
