# p2p-gather — single-launch P2P/UVA run-list gather (NVIDIA GB10, sm_121)

A single CUDA kernel that gathers many disjoint byte-runs from peer UVA
memory into one local scratch buffer, replacing the per-run
`cudaMemcpyPeerAsync` / `cudaMemcpy2DAsync` loop a coalescer (KVAAS
`PeerFetcher.fetch_pages_into_scratch`) pays for a fragmented hit prefix.
Run metadata is staged once into a per-launch `cudaMallocAsync` device
buffer (the default memory pool is tuned so the allocation is a cheap
internal pointer bump, not a driver syscall) and one kernel is launched;
there are no per-run CUDA API calls after the metadata is prepared.

## Kernel (pseudocode)

```cpp
// 1-D: grid.x tiles the longest run's bytes, grid.y = num_runs.
__global__ void gather_1d(const Run1D* __restrict__ runs, int n) {
  int r = blockIdx.y;
  if (r >= n) return;
  Run1D run = runs[r];                       // every block of r reads the same run → L2
  unsigned long long i = blockIdx.x * 256u + threadIdx.x;
  if (i < run.length) run.dst[i] = run.src[i];   // direct peer read over NVLink
}

// 2-D: grid.x tiles row width, grid.y = row, grid.z = run (independent caps).
__global__ void gather_2d(const Run2D* __restrict__ runs, int n) {
  int r = blockIdx.z;
  unsigned long long row = blockIdx.y;
  if (r >= n || row >= runs[r].height) return;
  Run2D run = runs[r];
  unsigned long long c = blockIdx.x * 256u + threadIdx.x;
  if (c < run.width)
    run.dst[row*run.dst_stride + c] = run.src[row*run.src_stride + c];
}

// Host: validate via stage_runs_1d (the oracle), copy descriptors into a
// per-launch device buffer, launch exactly one kernel. The buffer is
// freed with cudaFreeAsync before the entry returns (kernel already enqueued).
void p2p_gather_runs(uint8_t* dst, size_t cap, const void* const* src,
                     const size_t* off, const size_t* len, size_t n, stream) {
  auto staged = stage_runs_1d(dst, cap, src, off, len, n);   // host oracle validation
  if (staged.empty()) return;
  ScopedDevBuf meta(n * sizeof(Run1D), stream);             // pool-tuned, cheap
  cudaMemcpyAsync(meta.ptr, staged.data(), n*sizeof(Run1D), H2D, stream);
  gather_1d<<<grid,256,0,stream>>>(meta.ptr, n);
}
```

The full reference (host oracle + CUDA kernel + C ABI) lives in
`csrc/vkernels/comm/p2p_gather{.hpp,.cpp,.cu,_cuda.hpp,_c.h,_c.cu}`.

## What was implemented

- **Host reference** (`p2p_gather.cpp`): the always-compiled correctness
  oracle. `stage_runs_1d` / `stage_runs_2d` validate non-null sources,
  destination capacity, src/dst non-overlap (via `uintptr_t` comparisons,
  avoiding the UB of ordering pointers from different allocations) and
  mutually-disjoint output runs (O(N log N) sort, conservative bounding-box
  for 2-D), then a single `Stream::submit` copies every run. Fully
  unit-tested, 100% line + branch coverage.
- **CUDA kernel** (`p2p_gather.cu`, `vkernels::comm::cuda`): reuses the
  host's `stage_runs_*` for validation, stages run descriptors into a
  per-launch `cudaMallocAsync` device buffer and launches exactly one
  kernel. The default memory pool is tuned once
  (`cudaMemPoolSetAttribute` with `cudaMemPoolAttrReleaseThreshold =
  UINT64_MAX`) so freed memory is retained and a subsequent
  `cudaMallocAsync` is a pool-internal pointer bump, not a driver
  memory-acquisition syscall. This is safe across concurrent streams
  (each launch gets its own buffer, unlike a mutable `__constant__`
  symbol) and correct on every architecture (a plain device pointer has
  no Hopper `cudaErrorIllegalAddress` fault). Grid axes are bounded by
  `kMaxGridAxis = 65535` and `tiles()` checks for grid.x overflow.
- **C ABI** (`p2p_gather_c.h` / `p2p_gather_c.cu`, exported by
  `libvkernels_c`): `extern "C"` entry points taking raw pointers and a
  `cudaStream_t`, returning `vkernels_status_t` codes. C++ exceptions
  are caught inside the wrapper and mapped to
  `VKERNELS_ERR_INVALID_ARGUMENT` / `VKERNELS_ERR_INTERNAL`.
- **Legacy seam** `memcpy_peer_batch_async`: one `cudaMemcpyPeerAsync` per
  run, kept so the single-launch vs per-run property is assertable on the
  host and benchmarkable on device.
- **Benchmark** (`benchmarks/p2p_gather_bench.cu`): sweeps run count and
  fragmentation (1-D and 2-D) with raw `cudaEvent` and a median over
  iterations; no external dependency.

## Workload

- Device: NVIDIA **GB10**, compute capability **12.1**, CUDA 13.0 / driver
  580.95.05, single GPU per node. Measured on **ds5** (`dgx-spark-05`) and
  **ds6** (`dgx-spark-06`); the two nodes agree to within a few percent, so
  only ds5's numbers are tabulated below (ds6 reproduced them; see
  Caveats).
- Baseline: one **`cudaMemcpyPeerAsync(dst[i],0, src[i],0, len[i], stream)`**
  per run — the exact API the primitive replaces. On these single-GPU nodes
  `src` and `dst` are the same device (0→0); on a multi-GPU system `src`
  would be a peer device and the kernel/measurement are unchanged.
- Runs are disjoint and cover a contiguous destination. 50 timed iterations
  after 3 warmups; the table reports the median.

**Reproduce.** On a GB10 host with `/usr/local/cuda/bin/nvcc`:

```bash
cmake -S . -B build/cuda-bench -DCMAKE_BUILD_TYPE=Release \
      -DCMAKE_CUDA_COMPILER=/usr/local/cuda/bin/nvcc \
      -DVKERNELS_NVCC_EXECUTABLE=/usr/local/cuda/bin/nvcc \
      -DCMAKE_CUDA_ARCHITECTURES=121 \
      -DVKERNELS_BUILD_BENCHMARKS=ON -DVKERNELS_BUILD_TESTS=OFF
PATH=/usr/local/cuda/bin:$PATH cmake --build build/cuda-bench -j
./build/cuda-bench/benchmarks/p2p_gather_bench
```

> *Note on the metric:* this is a memory-copy primitive, not a compute
> kernel, so the template's "Achieved GFLOPS" column is reported as
> **Achieved GB/s** (destination bytes / single-launch time).

## Caveats and notes

- **Single-GPU stand-in for peer memory.** ds5/ds6 each have one GB10, so
  the baseline uses `cudaMemcpyPeerAsync` device 0 → 0 and the kernel reads
  a same-device allocation. This isolates and measures exactly the overhead
  the primitive removes — **per-run launch/driver cost** — which dominates
  the baseline for fragmented prefixes. On a real multi-GPU system, point
  `src_ptrs[i]` at peer memory and enable peer access before the launch;
  the kernel and the measurement are unchanged (the kernel issues direct
  peer reads over NVLink with no host staging).
- **Crossover.** For 1–~5 runs a per-run `cudaMemcpyPeerAsync` loop is
  faster (the single launch's metadata copy isn't justified). The
  single-launch kernel pulls ahead from ~8 runs and dominates through
  thousands of runs (40–77× at 2048 runs). This is the primitive's
  purpose: a coalesced prefix of dozens-to-thousands of pages.
- **Design: per-launch `cudaMallocAsync` over `__constant__`.** An earlier
  revision staged run descriptors in a `__constant__` symbol (with a
  `cudaMemcpyToSymbolAsync`). That faults with `cudaErrorIllegalAddress` on
  Hopper (sm_90) when the constant address is passed as a generic `const
  T*` kernel argument, and a single mutable `__constant__` symbol is unsafe
  across concurrent streams. The current design uses a per-launch
  `cudaMallocAsync` device buffer — correct on every arch, private to each
  launch — with the default pool tuned once so freed memory is retained
  and the allocation is a cheap internal pointer bump (not a driver
  syscall).
- **Correctness oracle.** The CUDA kernel reuses the host's fully
  unit-tested `stage_runs_1d` / `stage_runs_2d` for validation (capacity,
  non-null sources, src/dst non-overlap via `uintptr_t`, mutually-disjoint
  outputs via sorted bounding boxes). The host test
  (`tests/comm/test_p2p_gather.cpp`) is the byte-exact oracle; the C ABI
  test (`tests/comm/test_p2p_gather_c.cu`, CUDA-gated) exercises the
  status-code return path and byte-exact results on device.
- **ODR safety.** The CUDA launchers (`reduce.cu`, `gemm.cu`,
  `p2p_gather.cu`) live in a `cuda::` namespace so they coexist with the
  host reference objects as separate symbols — the full CUDA all-target
  build links without duplicate-definition errors.
- **ds5 vs ds6.** Both are identical GB10 nodes (sm 12.1, driver 580.95.05).
  ds6 reproduced ds5 within a few percent (e.g. 2048×2 KiB: ds5 76.84× vs
  ds6 78.06×; 2048×4 KiB: ds5 50.76× vs ds6 50.26×; 2-D 256 tiles: ds5
  6.61× vs ds6 6.25×; 8192 runs: ds5 19.24× vs ds6 25.69× — the larger
  pool-tuned allocation amortises even better on ds6).

## Journal

**What was done.** Implemented the single-launch P2P/UVA run-list gather
(`p2p_gather_runs` / `p2p_gather_runs_2d`) per issue #3, plus a C ABI
(`vkernels_p2p_gather_runs` / `_2d`) exported by `libvkernels_c`. The
primitive stages run metadata into a per-launch `cudaMallocAsync` device
buffer (pool-tuned for cheap reuse) and launches exactly one kernel,
replacing the per-run `cudaMemcpyPeerAsync`/`cudaMemcpy2DAsync` loop. Built
and benchmarked on ds5 and ds6 (GB10, sm_121); all 15 CUDA tests pass and
results are recorded under `docs/performance/`.

**Challenges.**
1. *No CUDA toolchain locally* — the `.cu` files had never been compiled, so
   the first real build surfaced latent infra bugs (nvcc flag handling in
   `Warnings.cmake`, an argument-order bug in `device.cpp`, an undefined
   `check_same` in `elementwise.cu`, ODR clashes in `reduce.cu`/`gemm.cu`).
   Fixed each minimally without touching host behaviour.
2. *`__constant__` faults on Hopper and is unsafe across streams.* The first
   CUDA design staged run descriptors in `__constant__` memory via
   `cudaMemcpyToSymbolAsync`. Reviewers flagged that taking the address of a
   `__constant__` symbol and passing it as a generic `const T*` kernel
   argument faults with `cudaErrorIllegalAddress` on Hopper (sm_90), and
   that a single mutable `__constant__` symbol is unsafe across concurrent
   streams. Switched to a per-launch `cudaMallocAsync` device buffer —
   correct on every arch, private to each launch — with the default memory
   pool tuned once (`releaseThreshold = UINT64_MAX`) so freed memory is
   retained and subsequent allocations are cheap internal pointer bumps.
3. *Shared-library / static-link interaction.* The C ABI test initially saw
   `cudaErrorInvalidResourceHandle` on the kernel launch because the test
   binary linked both the static `vkernels` (with CUDA kernels) and the
   `vkernels_c` shared library (which privately links its own `vkernels`).
   Resolved by adding a `NO_VKERNELS_LIB` option to `vkernels_add_test` so
   the C ABI test links only the shared boundary.
4. *Pointer-comparison UB and 2-D validation gaps.* Reviewers flagged that
   comparing `const uint8_t*` pointers from different allocations is UB and
   that `stage_runs_2d` lacked src/dst overlap and mutual-disjointness
   checks. Fixed both: `stage_runs_1d` and `stage_runs_2d` now compare via
   `uintptr_t`, and `stage_runs_2d` validates per-tile src/dst non-overlap
   (conservative bounding box) and sorted mutual-disjointness of output
   tiles — so the concurrent CUDA kernel (no inter-run ordering) can trust
   the staged metadata.

**Future work.**
- Benchmark on a true multi-GPU node (e.g. a 2×GH200 or 8×H100) with real
  peer memory and NVLink, and add a `cudaMemcpyPeerAsync` baseline that
  crosses devices to confirm the bandwidth-limited regime.
- A 2-D kernel using TMA / `cp.async.bulk` for large strided tiles, and a
  warp-specialised producer/consumer variant for overlapping the metadata
  fetch with the copy.
- Nsight Systems/Compute profiles of the single kernel vs the per-run loop
  to confirm the launch-overhead story quantitatively.
